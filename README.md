# AI-Powered A/B Test Analyzer

A portfolio project by **Brendan Hoffman** demonstrating how generative AI turns raw A/B test data into a boardroom-ready executive report — no statistics background required to read the output.

---

## What This Project Does

Most A/B test dashboards stop at the numbers. This project goes one step further: it takes those numbers, runs rigorous statistical analysis, and then uses the Claude AI API to generate a concise executive briefing that a VP could act on in five minutes.

The scenario is a homepage banner personalization test for a fictional e-commerce company (Evergreen Home & Outdoor). Control A shows a static promotional banner; Variant B shows a personalized banner featuring products from the visitor's browsing history.

**The output answers the questions executives actually ask:**
- Should we ship this?
- What's the business impact, in plain language?
- Where does it break down — which users don't benefit?
- What do we do next, and who owns it?

---

## How It Was Built

The project was built iteratively using **Claude Code** (Anthropic's CLI coding tool), with AI assistance throughout the development process — including statistics implementation, UI layout, prompt design, and visual styling. The workflow treated Claude Code as a collaborative development partner rather than a code generator: explaining intent, reviewing suggestions, and refining incrementally.

The dataset is synthetic, generated by `generate_test_data.py` to exhibit realistic patterns: a genuine lift for returning visitors, a near-zero effect for new visitors (the personalization engine has no history to work with), and plausible segment-level variation across device, channel, and geography.

---

## How It Works

The app is organized into four progressive tabs:

### Tab 1 — Executive Summary
High-level verdict and the three or four numbers that matter most. Designed to be the first thing a stakeholder sees.

### Tab 2 — Detailed Results
Full statistical evidence for each metric: conversion rate, banner click-through rate, bounce rate, average order value, and revenue per visitor. Each metric shows the observed lift, p-value, confidence interval, statistical power, and effect size.

### Tab 3 — Segment Analysis ("Who Does It Work For?")
Breaks results down by device type, user type (new vs. returning), acquisition channel, geography, day of week, and compound segment combinations (e.g., Mobile + Returning Visitors). Includes anomaly detection that flags segments where the variant significantly underperforms or reverses direction.

### Tab 4 — AI Summary
Sends the full statistical payload to Claude and streams back a structured executive briefing in real time. Also surfaces a **prompt transparency panel** showing exactly what prompt engineering techniques were used and why.

## Statistical Methodology

The stats engine (`stats_engine.py`) selects the appropriate test for each metric type:

| Metric | Test | Why |
|--------|------|-----|
| Conversion rate, CTR, bounce rate | Two-proportion z-test | Binary outcomes |
| Average order value, revenue per visitor | Welch's t-test | Continuous values, unequal variances |

For every metric, the engine also calculates:
- **Effect size** — Cohen's h (proportions) or Cohen's d (continuous means)
- **Observed statistical power** — how reliably the test could detect the observed effect
- **Minimum sample size** — what would be needed to reach 80% power
- **95% confidence intervals** on the lift

Cross-contaminated users (those who saw both variants) are detected and excluded before analysis.

## Prompt Engineering

The AI summary (`ai_summary.py`) uses seven deliberate techniques, all visible in the app's prompt transparency panel:

1. **Persona priming** — The system prompt establishes a senior analytics consultant presenting to a VP, anchoring tone and vocabulary.
2. **Structured output scaffolding** — A prescribed four-section format (Recommendation, What We Found, Where It Breaks Down, Next Steps) eliminates format ambiguity.
3. **Constraint layering** — Word limits, "no hedging" rules, and "quantify everything" directives each target a specific LLM failure mode.
4. **XML-tagged data blocks** — Input data is organized into labeled `<test_context>`, `<topline_results>`, `<segment_breakdowns>`, and `<detected_anomalies>` blocks for sequential reasoning.
5. **Few-shot quality anchoring** — A concrete example sentence shows the expected caliber of writing for the Recommendation section.
6. **Anti-pattern guardrails** — Explicit "do not" instructions prevent burying the lead, restating numbers without interpretation, and offering vague next steps.
7. **Grounding instruction** — A closing directive instructs the model to cite only numbers present in the data, reducing hallucination risk.

Temperature is set to 0.3 — analytical precision with enough variability for natural prose.

## Setup

```bash
# Install dependencies
pip install streamlit plotly pandas scipy numpy anthropic python-dotenv

# Run the app
streamlit run app.py
```

No API key is required — the AI-generated summary is included in the repo (`ai_generated_summary.md`) and displayed directly in the app. If you want to regenerate it live against the Claude API, set `ANTHROPIC_API_KEY` in your environment or a `.env` file.
